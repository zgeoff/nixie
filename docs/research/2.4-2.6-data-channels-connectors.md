# Data, channels and connectors

The research recommends keeping every primary copy of the owner's data on the owner's host: memory
as markdown in a git repo there, the event log in a database next to it, and only encrypted backups
leaving. For channels, Telegram meets every tier 1 need with the least work, but it holds the
conversation on its own servers, which conflicts with the principle that owner data stays home.
Voice fits as a pipeline around nixie's own turn. Each owner registers their own OAuth clients, and
a private deployment repo pins nixie's version and holds the owner's definitions. None of these
recommendations is a decision; the last section lists the decisions they feed, and several of them
pull against each other or against an earlier decision.

The findings come from 3 research tracks, as of 8 October 2026, with no spikes run:

- memory and data in [2.4-notes](./2.4-notes/)
- channels and voice in [2.5-notes](./2.5-notes/)
- connectors and deployment in [2.6-notes](./2.6-notes/)

Each notes file lists the spikes that would settle its open questions.

## Memory

The [memory notes](./2.4-notes/memory-models.md) recommend markdown files in a git repo on the
owner's host as the store of record. The owner reads, edits, diffs and exports memory with ordinary
tools, and git gives a version for every write. Every memory write is a nixie tool with a
memory-write effect, so the rules from [0004](../decisions/0004-rule-engine.md) decide which writes
apply at once and which become proposals on the digest sheet. nixie sets each write's origin, never
the model, and a write from a tainted thread always reaches the owner. Consolidation runs on a
branch and merges only when the owner approves the diff. A search index rebuilt from the files
starts with full-text search, and embeddings follow only if they measurably help.

The evidence supports review over filtering: memory poisoning succeeded against every shipped agent
tested, and the best prompt-injection filter caught 67.67% of attacks. Every vendor's retrieval
score is self-reported, and the LoCoMo benchmark's answer key is 6.4% wrong.

The cost of files is a gap between git and the event log's transaction. An approval commits in the
database and the memory change commits in git, so after a crash the two can briefly disagree. A
check for an existing commit stops a write from repeating but does not close the gap. Memory as rows
in the database closes it, at the cost of editing memory in an ordinary editor.

## Where data lives

The [storage notes](./2.4-notes/data-and-storage.md) recommend keeping every primary copy on the
owner's host and sending personal data off it only through restic or Kopia, which encrypt names,
sizes and history before upload. git-crypt leaks file names, sizes and history to the git host.
Neither database encrypts at rest under Bun, so disk encryption covers the database, the memory repo
and the SDK's session files.

For decision 0001's open question, the notes recommend Postgres through `kysely-postgres-js` on
Bun's native SQL client. The Kysely project maintains that driver, a second host needs no new layer,
and Postgres can wake a worker without polling. The cost is a service to run and a major upgrade
each year. SQLite is the strong alternative if nixie never runs on a second host: it removes the
service, and the file is its own export, but its Kysely dialects on Bun are stale or kept by one
person.

The [versioning notes](./2.4-notes/definition-versioning.md) recommend stamping every record with a
hash of the persona, job and policy definitions in force, next to the rule ID. Snapshots live in a
table in the event log's database, so a replay needs only the database and its backup. The
deployment repo's commit is stored as a label, and runtime rules carry the ID of the approval that
created them.

## Channels

The [channel notes](./2.5-notes/channels.md) recommend Telegram as the first channel. It meets every
tier 1 need with the least work:

- callbacks that nixie can verify
- room for a proposal ID in each button, for an approval bound to one proposal under
  [0006](../decisions/0006-approval-record.md)
- streamed replies that the owner can stop
- push after one `/start`

Telegram stores the conversation unencrypted on its servers, and a compromised Telegram account can
press approval buttons. Self-hosted Matrix keeps messages home and gives the strongest check of the
sender, but it has no buttons, so approvals need the page below.

For the always-ask set and the digest sheet, the notes recommend an approval page that nixie hosts,
behind a passkey. A Telegram Mini App, a web push or a Matrix link can open it, so it works with any
chat channel. No chat account compromise can forge a passkey, and the cost is an extra tap on the
highest-risk approvals.

Three channels stay out of tier 1. WhatsApp's terms ban general-purpose AI assistants. iMessage
needs a Mac bridge with no signed webhooks. Signal has no buttons and an unclear position on bots.
Email and SMS can push a notice and a link, and never carry an approval on their own.

## Voice

The [voice notes](./2.5-notes/voice.md) recommend a pipeline of speech-to-text, nixie's own model
turn, and text-to-speech, built on Pipecat. Pipecat's licence, turn detection and voice activity
detection are open, and its transcript holds only what the owner heard. The costs are a Python
process beside the Bun core and a delay of about 1.3 to 1.5 s from the owner's speech to the reply,
which the Agent SDK's own turn overhead may push higher. Anthropic offers no voice API.

OpenAI's GPT-Live 1, with nixie handling the tool calls, is the hosted alternative: OpenAI runs the
voice, and nixie keeps the conversation, the tools and the model behind them. OpenAI then hears all
the owner's audio. A local pipeline on a GPU host keeps audio private at lower quality.

The [transport notes](./2.5-notes/transports.md) recommend starting with voice notes on the chat
channel, then a web client that nixie serves over WebRTC with a TURN relay. On iOS, a web client
loses the microphone when the app goes to the background or the screen locks. A native app is the
route to calls with the screen locked, or to nixie ringing the owner. Telnyx is the phone-line
option, at about $1 a month plus under $0.01 a minute.

## Connectors and MCP

The [MCP notes](./2.6-notes/mcp.md) recommend 4 interfaces of nixie's own, because MCP has no
counterpart for them: a channel adapter, a trigger source, a connector, and a credential store.
nixie takes tools from MCP. MCP revision 2026-07-28 is stateless, tasks are an official extension,
and events exist only as an open proposal.

Third-party MCP servers reach the model through a nixie proxy, as
[0002](../decisions/0002-approvals.md) requires. The proxy records each tool's description and
schemas by hash, the owner declares the tool's effects, and a changed hash asks again. Taint follows
the output schema field by field: booleans, numbers, enums whose values the owner reviewed, and
dates that nixie parses stay clean. Any other string taints, URLs and patterned strings included,
because each can hold an instruction. Most third-party tools return free text, so they taint until
someone writes a typed wrapper. Connectors for the owner's own accounts stay nixie code, so the
owner's tokens never leave nixie's host.

The [connector notes](./2.6-notes/connectors.md) recommend that each owner register their own OAuth
clients, published to production unverified. Google's personal-use exception, for fewer than 100
users, then needs no verification and no security assessment, and testing mode would force a fresh
consent every 7 days. Microsoft Graph needs a free Azure account. iCloud works only with an
app-specific password, and Reminders and Notes have no third-party route. Third parties report that
Google blocks unverified apps from restricted scopes such as full Gmail access; no Google page
confirms it, and the 8-day spike in the connector notes would show it.

For search, the notes recommend SearXNG, which runs on the owner's host but forwards each query to
upstream search engines, which see the query and the host's address, or Kagi, which keeps no query
log against the account at $12 per 1,000 searches.

## Deployment

The [deployment notes](./2.6-notes/deployment.md) recommend a private repo that pins nixie's
version, holds persona, jobs and policy, and references secrets. nixie ships as an OCI image run by
Compose, secrets sit in the repo encrypted with sops and age, and upgrades arrive as pull requests
from a dependency bot, with a database backup before each migration. nixie binds to loopback and is
reached over Tailscale Serve. A public route is needed only for a channel or connector that relies
on webhooks; Telegram works on long polling with no inbound route.

## Tensions

- **Telegram and "owner data stays home".** The principle requires that personal data stay on hosts
  the owner controls. Telegram holds the conversation on its servers, and Matrix keeps it home at
  the cost of buttons and some polish.
- **Search results and decision 0005.** [0005](../decisions/0005-effects-and-taint.md) gives "a
  search API's JSON" as a typed result that leaves the main thread clean. In every provider, the
  titles and snippets in that JSON are page text, so only the dates and scores are fully clean. A
  URL can hold text in its path, so it is only partly clean. A search tool either returns URLs
  alone, and the model sees less, or its results taint the main thread.
- **The deployment repo on a git host.** The deployment repo holds the owner's persona, jobs and
  policy, and a hosted git service is a third party. Self-hosted git, or the repo kept off any host,
  keeps the definitions home.
- **Approval during a voice call.** Under [0002](../decisions/0002-approvals.md), a spoken yes is
  not an approval. A call needs a route to the button or the approval page, or the proposal waits
  until the call ends.
- **A Python process beside a Bun core.** Pipecat is the strongest open voice framework, and it runs
  in Python.
- **The SDK turn and the voice budget.** The time from an Agent SDK turn's start to its first token
  is unmeasured, and it decides whether nixie's own turn fits a voice conversation.

## Decisions this research feeds

Each item is open, with the research recommendation first:

- **The memory store:** markdown in a git repo on the owner's host, or rows in the event log's
  database.
- **Which memory writes skip review:** writes from the owner in an untainted conversation, or none.
- **How nixie forgets:** crypto-shredding, a rewrite of git history, or a tombstone.
- **The event log's database:** Postgres, or SQLite if nixie never runs on a second host.
- **Definition versioning:** a snapshot hash on every record, with snapshots in the database.
- **The first chat channel:** Telegram, or self-hosted Matrix.
- **High-risk approvals:** a passkey page that nixie hosts, or buttons on the chat channel for every
  approval.
- **The voice stack:** a Pipecat pipeline, GPT-Live 1, or a local pipeline.
- **Voice transports:** voice notes first, then a web client, with a native app or a phone line
  later if the owner wants them.
- **nixie's own interfaces:** a channel adapter, a trigger source, a connector and a credential
  store, with tools from MCP.
- **Third-party MCP servers:** a proxy that pins tools by hash and judges taint by field type.
- **Connector authorization:** OAuth clients that each owner registers.
- **The search provider and its result shape:** SearXNG or Kagi, and URLs alone or tainted snippets.
- **Deployment:** a private repo, an OCI image under Compose, sops and age, and Tailscale, with
  where the repo lives still open.

# Research brief

Research settles these questions before design starts. Each track becomes one research sub-phase, and each question traces to an open question in the brainstorm or to a check left open while choosing to build.

## 2.1 Landscape and architecture models

- How is each hosted assistant built, as far as its docs, behaviour, and limits reveal? This covers the always-on agents from OpenAI, xAI, Google, and Anthropic.
- How are the open-source agents built? This covers OpenClaw, Hermes Agent, Nanobot, NanoClaw, ZeroClaw, IronClaw, and Letta.
- Which architecture models recur across them, and which fit [Principles](./1.3-principles.md)?
- Does a framework such as eve or Mastra fit as a skeleton, or does nixie build its core on an agent runtime directly?

## 2.2 Core and runtime

- Where does the adapter boundary sit, given that the Claude Agent SDK is a whole harness with its own loop, tools, hooks, and permission system?
- How does nixie enforce its own policy inside a runtime that has its own permission system, so the runtime never refuses what nixie allows?
- Which parts form the core, and which sit behind an interface?
- Which engine gives execution that resumes at its last step after a restart, on hosts the owner controls?
- How does a message from the owner reach a task that is already running?

## 2.3 Policy and trust

- Which policy models fit a deterministic engine with a risk stance per context: rule languages, typed-action classifiers, or a mix?
- How are approvals stored, scoped, expired, and replayed?
- Can the imp credential broker filter requests by HTTP method and path, so a grant can be read-only?
- Can the imp credential broker refresh an OAuth token, or does it inject only a static one?
- How does a task that reads untrusted content run with no route out?

## 2.4 Memory and data

- Which memory model fits a store that the owner can read, edit, and export, with review of every write?
- Where does personal data live, given that a git host is a third party?
- How are definitions of persona, jobs, and policy versioned, and tied to each record?

## 2.5 Channels and voice

- Which chat channels support two-way conversation, pushes, and a reliable owner identity?
- Which realtime voice stacks support interruption and run with a session that nixie owns?
- Which transports carry voice to the owner, such as a web or app client, a chat app's voice notes and calls, or a phone line, and what does each take to set up?

## 2.6 Connectors and deployment

- What does the current Model Context Protocol (MCP) spec cover, and which interfaces does nixie define beyond it for channels, triggers, and credential brokering?
- What does each first connector take to authorise, such as Google's OAuth verification for Gmail scopes?
- How does a deployment repo plug into the owner's existing infrastructure?

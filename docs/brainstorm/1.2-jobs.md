# Jobs

A deployment defines its own jobs, and the system ships none. The table lists the kinds of job the system must be able to run. Each kind carries an example of a job a deployment might define.

| Kind                                   | Example                                                     | Trigger             | Risk   |
| -------------------------------------- | ----------------------------------------------------------- | ------------------- | ------ |
| Scheduled briefing                     | A morning report                                            | Schedule            | Low    |
| Reminder and follow-up                 | "Call back about the booking at 3 pm"                       | Time or event       | Low    |
| Background work, reported when ready   | "The research you asked for is done"                        | Event               | Low    |
| Upkeep of an owner's service           | Inbox triage, calendar, task list, file cleanup             | Request or schedule | Medium |
| Acting in the outside world            | A purchase, a phone call, an SMS                            | Request             | High   |
| Capture and recall                     | Save a link now, find it by meaning later                   | Request             | Low    |
| Research and making things             | A reading detour, a short write-up, an image                | Request or schedule | Low    |
| Work on private data, on a local model | Summarise medical or financial records                      | Request             | Medium |
| Steering other agents                  | Start coding-agent sessions, write their briefs, check their results | Request or event | Medium |

Conversation is not a kind of job. Every job runs through it, so it is a requirement.

## Scope

All nine kinds are in scope for the first deployment. The order of delivery is a design decision.
